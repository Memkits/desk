# Langfuse v4 核对记录（源码 langfuse/langfuse @ 6918181，2026-11-05，web v4.76.0；langfuse-python 5.2.0）

## 上报
- OTLP 入口 `POST /api/public/otel/v1/traces`（web/src/pages/api/public/otel/v1/traces/index.ts）：接受 `application/x-protobuf` 与 `application/json`，支持 gzip；Basic Auth；`x-langfuse-ingestion-version` > 4 返回 400。
- 先校验 traceId/spanId；一个坏 span 整批 400（常见原因：OTLP logs 打到 traces 端点）。
- Python SDK 5.2.0 默认头：Authorization、x-langfuse-sdk-name=python、x-langfuse-sdk-version、x-langfuse-public-key、x-langfuse-ingestion-version=4（langfuse/_client/span_processor.py）。
- SDK 属性名：langfuse.trace.name / user.id / session.id / langfuse.trace.tags / langfuse.trace.metadata / langfuse.observation.{type,input,output,metadata,level,status_message,model.name,model.parameters,usage_details,cost_details,prompt.name,prompt.version} / langfuse.environment / release / version（langfuse/_client/attributes.py）。
- `propagate_attributes(..., as_baggage=False)`：把 trace 级属性写到上下文里每个 span；as_baggage=True 时走 OTel Baggage 跨服务（langfuse/_client/propagation.py）。
- 服务端还识别 gen_ai.*（OTel GenAI 语义约定）、ai.*（Vercel AI SDK）、llm.*（OpenInference）等。

## 转存
- OTel：整批 resourceSpans 作为一个 JSON 对象上传 `{LANGFUSE_S3_EVENT_UPLOAD_PREFIX}otel/{projectId}/yyyy/mm/dd/hh/mm/{uuid}.json`，BullMQ `otel-ingestion-queue` 只带 fileKey（packages/shared/src/server/otel/OtelIngestionProcessor.ts:364）。
- 旧 `/api/public/ingestion`：按 eventBodyId 分组，`{prefix}{projectId}/{entityType}/{entityId}/{eventId}.json`，队列 `ingestion-queue`，非 OTel 事件默认延迟 ≤5 s，UTC 23:45–00:15 用 LANGFUSE_INGESTION_QUEUE_DELAY_MS（packages/shared/src/server/ingestion/processEventBatch.ts, eventBucketPath.ts）。
- 主/次队列：项目可被分到 secondary 队列（高吞吐隔离）。

## 处理（worker/src/queues/otelIngestionQueue.ts）
- 下载 S3 → （EE）脱敏回调 → OtelIngestionProcessor.processToEvent → IngestionService.createEventRecord（prompt 查找、模型匹配、tokenize、成本计算、metadata 扁平化）→ 观测级评估调度 → writeEventRecord（可选 field overflow）→ ClickhouseWriter 批量写 events_full。
- 写路径判定 resolveOtelWritePath：direct_header（python ≥4.0.0 / javascript ≥5.0.0 / ingestion-version≥4）> direct_env（NATIVE_OTEL_BEHAVIOUR=direct）> direct_scope（scope 含 langfuse 且版本满足）> direct_org_cutoff（仅 Cloud，非 Langfuse SDK）> dual。
- 注意：文档的 Python 4.7.0 / JS 5.4.0 是 SDK 侧“每个 span 都带上 trace 属性”的版本；服务端直写阈值是 4.0.0 / 5.0.0。
- ClickhouseWriter 默认：批 1000 条、间隔 1000 ms、最多 3 次重试（worker/src/env.ts）。
- metadata 扁平化：嵌套对象 → 点号路径 `a.b.c`，非字符串值 JSON.stringify，存为 metadata_names[] / metadata_values[] 两个平行数组（packages/shared/src/server/otel/utils.ts flattenJsonToPathArrays）。
- Field overflow：LANGFUSE_OBSERVATION_FIELD_OVERFLOW_ENABLED=false 默认；阈值 LANGFUSE_OBSERVATION_FIELD_SIZE_LIMIT_BYTES=2 MiB；超限的 input/output/metadata 值上传到媒体桶，行内留引用。
- EE 脱敏：LANGFUSE_INGESTION_MASKING_CALLBACK_URL，超时 500 ms，FAIL_CLOSED 默认 false，重试 1 次，可透传指定请求头；需要企业许可证；在 worker 下载 S3 之后执行（原始桶里是未脱敏数据）；fail-closed 丢弃时日志留 S3 key，可用 worker/src/scripts/replayIngestionEventsV2 重放。

## 存储（packages/shared/clickhouse/migrations/canonical）
- events_full（0039）：ReplacingMergeTree(event_ts, is_deleted)；PARTITION BY toYYYYMM(start_time)；ORDER BY (project_id, toStartOfMinute(start_time), xxHash32(trace_id), span_id, start_time)；SAMPLE BY xxHash32(trace_id)；index_granularity_bytes 64Mi；DateTime64(6)；bloom_filter 索引 span/trace/user/session；text 全文索引（splitByNonAlpha）在 lower(input)/lower(output)/metadata；ngram 索引（0043、0049）。
- 列：trace 级属性（trace_name、user_id、session_id、tags、release、version、environment）直接在行上；cost 拆分列 MATERIALIZED；total_cost ALIAS cost_details['total']；input_length/output_length MATERIALIZED；experiment_* 列；source / service_name / scope_name / telemetry_sdk_* / ingestion_api_key / ingestion_sdk_*；blob_storage_file_path 指回 S3 原件；event_bytes。
- events_core（0040）+ events_core_mv（0041）：同结构，input/output/每个 metadata 值 leftUTF8(…, 200)；部分 bloom 索引不同。
- observations_batch_staging（0038）：3 分钟分区（s3_first_seen_timestamp），TTL 48 h，ttl_only_drop_parts。
- v3 traces（0001）/ observations（0002）：ReplacingMergeTree，metadata 是 Map(LowCardinality(String), String)。
- 读路径：逻辑表 `events` 由编译期路由选 events_core 或 events_full（读到被截断列才去 full），metadata 用 mapFromArrays(arrayReverse(names), arrayReverse(values)) 还原（packages/shared/src/server/query-ast/eventsRouting.ts, compile.ts）。

## 双写传播（worker/src/features/eventPropagation/handleEventPropagationJob.ts）
- Redis 游标 `langfuse:event-propagation:last-processed-partition`，每次处理下一个 3 分钟分区，且分区要早于 now() − LANGFUSE_EXPERIMENT_EVENT_PROPAGATION_PARTITION_DELAY_MINUTES（默认 10）。
- SQL：staging FINAL LEFT JOIN（traces 取 LIMIT 1 BY 最新一行，时间窗 ≤7 天）→ INSERT events_full；parent_span_id 缺省为 `t-<trace_id>`；metadata = mapConcat(obs.metadata, trace.metadata)，observation 优先；source = otel-dual-write / ingestion-api-dual-write；排除 24 h 内的实验 trace；parallel_view_processing=1；超时 30 min。
- 健康检查阈值 LANGFUSE_EVENT_PROPAGATION_STUCK_THRESHOLD_MINUTES 代码默认 35（文档写 15）。

## 回填（worker/src/backgroundMigrations）

## 迁移开关（worker/src/env.ts）
- WRITE_MODE legacy|dual|events_only（默认 events_only）；NATIVE_OTEL_BEHAVIOUR dual_write|direct（默认 direct）；非法组合启动即报错：legacy+direct、events_only+dual_write、events_only 但 ALLOW_PREVIEW_OPT_IN=false。

## 导出（worker/src/features/blobstorage/handleBlobStorageIntegrationProjectJob.ts；packages/shared/src/server/repositories/events.ts）
- 目录 observations_v2/（即 events 表）、scores/、manifests/；格式 Parquet/CSV/JSON/JSONL(.gz)。
- 选了 io 或 metadata 字段组才读 events_full，否则读 events_core；时间窗按 start_time [min, max)；LIMIT 1 BY span_id, project_id 去重。
- JSONL 可走 raw passthrough：ClickHouse JSONEachRow 直出；Parquet 直出时 latency 在 SQL 中换算为秒。
- 字段组（packages/shared/src/domain/observation-field-groups.ts）：core, basic, time, io, metadata, model, usage, prompt, metrics, trace_context；导出另含 tools。

## 补充核对（脱敏 / 大体积 / 对接）
- 服务端脱敏回调：POST JSON（整批 resourceSpans 数组），请求头 Content-Type、X-Langfuse-Org-Id、X-Langfuse-Project-Id + 透传头；响应必须是同结构 JSON；重试退避 100·2^(n−1) ms 封顶 1 s；fail-open 时用原始数据继续；只作用于 OTel 路径（worker/src/queues/otelIngestionQueue.ts、prepareOtelBatch.ts），旧 /api/public/ingestion、Scores API 不经过；脱敏结果不回写 S3，blob_storage_file_path 指向原始文件。
- 开启 early media extraction 时顺序：脱敏 → 校验 → 抽取内联媒体（prepareOtelBatch.ts）。
- Python SDK 客户端：Langfuse(mask=fn)，对 input/output/metadata 先抽媒体再 mask（langfuse/_client/span.py _process_media_and_apply_mask）。
- SDK 媒体：识别 data:*;base64 URI、Anthropic {type: base64}、Gemini inline_data 等 → 通过 /api/public/media 申请预签名上传 URL（按 sha256 去重，已存在则 upload_url 为空）→ 字段内替换为 @@@langfuseMedia:type=…|id=…|source=…@@@。
- 媒体对象键：{LANGFUSE_S3_MEDIA_UPLOAD_PREFIX}{projectId}/{mediaId}.{ext}；mediaId 由 sha256 派生，同项目同内容复用；单文件上限 LANGFUSE_S3_MEDIA_MAX_CONTENT_LENGTH 默认 1,000,000,000 字节。
- 体积上限：OTel 请求体 LANGFUSE_OTEL_INGESTION_MAX_BODY_BYTES 默认 512 MiB（压缩前后都检查，超限 413 并关闭连接）；16 MiB 以上记警告；旧 /api/public/ingestion 请求体 4.5 MB；Python SDK 可用 LANGFUSE_OTEL_MAX_BATCH_SIZE_BYTES 限制每批大小。
- 服务端媒体抽取 LANGFUSE_OTEL_MEDIA_UPLOAD_ENABLED 默认 false；EARLY 抽取（Rust 原生）默认 false。
- 字段溢出替换为 @@@langfuseMedia:type=text/plain|id=…|source=field_size_limit@@@，上传失败则保留原值。
- ClickhouseWriter 遇 ClickHouse JSON 过大 / Node 字符串长度错误：批次对半拆分重试；单条仍失败则 input/output 超过 1M 字符截到前 500K + "[TRUNCATED: Field exceeded size limit]"（jsonRecords.ts）；该兜底按 metadata 对象处理，不覆盖 events 表的 metadata_values 数组。
- user_id 来源顺序：span 属性 langfuse.user.id / user.id / …metadata.langfuse_user_id / ai.telemetry.metadata.userId → 资源属性 langfuse.user.id / user.id → user.name。session_id 还识别 gen_ai.conversation.id。批内不会从根 span 继承。
- events_only 下旧 /api/public/ingestion 只接受 score-create，其余事件 400 并说明未存储。
- 导出对象键：{prefix}{projectId}/{table}/{maxTimestamp}.{ext}，时间格式 toISOString 去掉毫秒、冒号换成连字符，如 2026-11-06T10-00-00（worker/src/features/blobstorage/manifest.ts）；清单 {prefix}{projectId}/manifests/{maxTimestamp}.json。
- Python SDK mask 签名 mask(*, data, **kwargs)；mask 抛异常时用兜底值 "<fully masked due to failed mask function>" 替换（metadata 字典逐键替换），即客户端是失败即遮蔽（langfuse/_client/span.py _mask_attribute）。
