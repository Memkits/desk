1 架构与数据流

两个自有进程：Web（Next.js，界面与所有接口，含上报）和 Worker（Express，处理上报、评估、导出）。v4 没有新增服务。

存储内容
PostgreSQL ≥ 15用户、组织、项目、API 密钥、提示词、数据集、评估配置、媒体记录（media 表）
ClickHouse ≥ 25.12追踪数据（events_full / events_core）、评分（scores）；v3 表 traces / observations 仍存在
Redis / Valkey ≥ 7.0BullMQ 队列，API 密钥与提示词缓存，双写游标
S3 / Blob原始上报事件（事件桶）、媒体与溢出字段（媒体桶）、导出文件
SDK / 埋点→ OTLP →Web 校验→ 整批 JSON →S3 事件桶+ 地址 →Redis 队列→Worker 下载·（脱敏）·转换·补全→ 批量 →ClickHouse events_full→ MV →events_core

9 脱敏

位置机制覆盖失败行为局限
① 客户端 SDKLangfuse(mask=fn)，签名 fn(*, data, **kwargs)；对 input/output/metadata 先抽媒体再 mask该 SDK 创建的 span抛异常 → 整段替换为 <fully masked due to failed mask function>（metadata 字典逐键）每个应用都要接；第三方埋点不经过
② OTel Collectorattributes / transform 处理器改写或删除属性经过采集器的所有 span取决于采集器配置I/O 是整段 JSON 字符串；规则语言弱
③ 服务端回调（EE）Worker 下载 S3 后 POST 整批给回调，用返回结果继续仅 OTel 路径默认放行（原始数据入库）；FAIL_CLOSED=true 丢弃整批并记录 S3 key需企业许可证；旧 REST、Scores API 不经过；S3 原件未脱敏

建议的三层方案

  1. 客户端：SDK mask 处理确定字段（手机号、证件号）；媒体在此抽走。
  2. 网关：OTel Collector 作为唯一入口；统一加 x-langfuse-ingestion-version: 4；补租户资源属性；删除不允许出域的属性；限制批大小；采样保留根 span。
  3. 服务端：脱敏回调 + FAIL_CLOSED=true，做模型识别等复杂处理；事件桶与媒体桶 SSE-KMS + 最小权限 + 短生命周期；打开字段溢出。
  4. 导出侧：导到自有桶，先读清单，按 id 去重，用 metadata 数组还原结构；回查原件用 blob_storage_file_path。

14 改造风险清单

  • 同一 span 重复上报 → 两条记录（读取不保证去重）。
  • trace 属性未复制到子 span → 子 span 按用户/会话查不到。
  • 未识别属性进 metadata.attributes / metadata.resourceAttributes，嵌套键不能直接过滤。
  • events_only 下 /api/public/ingestion 只收评分。
  • 脱敏回调放行模式下，回调故障期间未脱敏数据入库；S3 原始事件始终未脱敏。
  • 大值放在 metadata 时不受写入兜底截断，可能导致写入失败；打开字段溢出。
  • 导出：latency 单位随创建日期不同；Parquet 缺单价列；导出未选 io/metadata 时内容是截断的。
  • 采集器采样丢掉根 span → 层级断裂、根上的整体输入输出缺失。
